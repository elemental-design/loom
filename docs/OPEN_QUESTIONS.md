## Pre-existing, from design phase (not blocking M0–M4)

- Slots: how much layout authority do nested `child` slots carry? (Deferred with `child` params; see 06-deferred.)
- Icon set normalization for SwiftUI/Compose (SF Symbols ↔ lucide mapping table). Needed at SwiftUI target only.
- Responsive breakpoints: lean toward per-target bindings, not spec. Needed when `viewports` land.

- T02: Spec's `generated/tokens.ts` has a bare `declare module "@loom/primitives"` augmentation, which fails typecheck (TS2664) when nothing else in the program imports that module. Chose: emit `import type {} from "@loom/primitives"` as the first line after the header. Also added `generated`, `loom.config.ts`, `loom.tokens.ts` to demo-ds tsconfig `include`, and moved `tsx` to compiler `dependencies` (config loader uses `tsx/esm/api`).
- T05: Verbatim fixtures fail typecheck: object-literal lookups (`({ sm: 2, ... })[s]`) widen to `number`/`string`, not `SpacingKey`/`ColorName`. Chose: add `as const` to those three literals in Button/Badge (spec 03's subset should confirm `as const` is allowed). Also set demo-ds tsconfig `moduleResolution: Bundler`/`module: ESNext` because fixtures import `../Badge/Badge.loom` without extension (fails under NodeNext).
- T06: 04-ir.md's Badge example shows `color` as a `lookup`, but the 07 fixture defines `fg` as `t === "danger" ? "onDanger" : "onAccent"`, which extracts to a `cond` (helper inlining is faithful, no ternary→lookup rewriting). Chose: keep the fixture and emit the `cond`; the Badge golden test asserts the example with `color` as that `cond`. Also: extraction stops at the first error per file; check order is LOOM106, 109, 108, 101, 105, then body.
- T07: (1) LOOM205/207 apply to every style prop (per spec 03's style-prop list), including `lines`, `Icon.size`, and px `width`/`height`; a `number`-param `width` is therefore LOOM205. (2) LOOM210 is unreachable through `loom lint` because extraction already aborts with LOOM108 on a missing `loom` export; the rule exists for direct `lintFiles` use. (3) Extractor position map keys: `nodeId` for elements and `nodeId@prop` for attributes. (4) A raw-color literal reports only LOOM202, not also LOOM203. (5) LOOM208 is reported on the `loom` declaration of the later file in path order.
- T08: (1) Spec's ZStack alignment table is elided ("9 entries; table in code"). Chose: equal vertical/horizontal → `place-items-<v>`, else `items-<v> justify-items-<h>`. (2) `defaultVariants` for a boolean param with no default emits `false`, otherwise `undefined` would skip the `false` variant (spec says omit). (3) Icon renders through a generated per-file `LoomIcon` helper (lucide `icons` map, kebab→Pascal at runtime, `name` optional) because `name` may be a param. (4) Text/Icon/Image/ZStack/Divider/Pressable defaults (e.g. `text-foreground`, `size-5`, `object-cover`, `place-items-center`, `bg-border`, `h-px`) are added as literal props before class evaluation. (5) Codegen errors are reported as `LOOMxxx <ir.source>:1:1` because the IR carries no positions; gen stops writing if any component fails. (6) `Divider.inset` uses `mx`/`my` and requires a static `axis`; `role` must be static. (7) Orphan drift messages use LOOM320 with the standard `path:line:col` format rather than the spec's literal `LOOM320 <path> ...`. (8) Added `packages/compiler/vitest.config.ts` (alias `@/lib/utils` to a test stub) so the render test can import generated files.
- T09: (1) The three host packages are declared as optional `peerDependencies` with `peerDependenciesMeta.optional`, and typechecked against ambient stubs in `src/native/host-shim.d.ts` that declare only the members `Host` uses (`render` for Sketch/Figma is included because the consumer `.sketch.tsx`/`.figma.tsx` examples import it). (2) No-host `Pressable` falls back to a `View`; `onPress` is not forwarded, so it is provably inert, and the pressed style is only merged when the host has a `Pressable`. (3) Native ZStack requires numeric `width`/`height` (throws LOOM302) because children are absolutely positioned and cannot size the container; the wrapper Views use `alignItems`/`justifyContent` to place each child inside an edge-pinned absolute View. (4) Icon renders a `size×size` View with `accessibilityLabel={name}` and warns `LOOM303` once per name per `createPrimitives` call in dev (`process.env.NODE_ENV !== "production"`); real glyph support is out of scope. (5) Error codes: LOOM300 unknown color/space/radius/typography key (message: `LOOM300 <primitive>: unknown <kind> "<key>"`), LOOM301 missing ThemeProvider, LOOM302 ZStack size, LOOM303 Icon placeholder. (6) `hugging` emits `alignSelf:"flex-start"` only on the parent's cross axis (a row parent's `width` or a column parent's `height` gets no alignSelf, matching web's flex `0 0 auto` behavior on the main axis). (7) Divider uses a literal `1` thickness (not `StyleSheet.hairlineWidth`, absent in Sketch/Figma); `inset` maps to `marginVertical`/`marginHorizontal` (web uses logical `margin-inline`/`margin-block`; RN has no logical margins). (8) Text `align` maps `start→left`/`end→right` (RN has no logical textAlign); typography values are spread into the style so `fontSize`/`lineHeight`/`fontWeight`/`fontFamily`/`letterSpacing` come from the theme. (9) The `.` export gained a `react-native` condition pointing at `src/native/rn.ts`; consumer `Badge.sketch.tsx`/`Badge.figma.tsx` import `@loom/primitives/sketch`/`/figma` and add a triple-slash reference to `host-shim.d.ts` (the shim is a package file, not shipped types). (10) `pnpm-workspace.yaml` `allowBuilds` gained `node-sketch-bridge` — installing the optional `react-sketchapp` peer (pulled in transitively during install) needs its native build script; the package itself is still only a dev-time resolution, never imported by tests.
